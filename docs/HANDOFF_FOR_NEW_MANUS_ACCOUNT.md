- سبق أن رفض Manus ربط مورد المشروع الأصلي لأن الحساب الحالي لا يملك صلاحية عليه. الـResource URI أو مشاركة ملف لا يمنحان هذه الصلاحية. **لا تعاود محاولة إرفاق URI قديم، ولا تطلب من المستخدم بيانات دخول الحساب القديم أو كلمة مروره.**
- أنشئ مشروع WebDev جديدًا مملوكًا للحساب الجديد، مستوردًا من المستودع والفرع `main`. هذا يمنح الموقع رابطًا جديدًا مستقلًا وقاعدة بيانات جديدة فارغة. GitHub ينقل الشيفرة والوثائق فقط، ولا ينقل ملكية مشروع WebDev أو قاعدة بياناته أو أسراره.
- الرابط القديم `https://studynivo2-j4dgwvrg.manus.space` لم يُعدّل أو يُنشر إليه شيء في هذه المتابعة؛ سيظل على الإصدار السابق إلى أن يملك صاحبه الأصلي المشروع وينشر من حسابه. **لا تعد المستخدم بتحديث الرابط القديم.**
- مشروع WebDev مستقل أُنشئ خلال هذه الجلسة لتجربة الإعداد، لكنه غير منشور ولا يُعتمد عليه للحساب الجديد؛ ربط GitHub لا ينقل ذلك المشروع أو قاعدة بياناته. لا حاجة لمعرف المورد الخاص به.

## ما يتضمنه كود التطبيق على `main`

عند خط الأساس `b2b8bd2`، يتضمن التطبيق React/Vite/TypeScript للواجهة وExpress/tRPC/Drizzle/MySQL للخادم، إضافة إلى الإصلاحات والميزات التالية:

- فحص Origin وحماية CSRF، وإبطال الجلسات من الخادم، وتحديد معدل محاولات المصادقة.
- جلسات موقعة باستخدام `STUDYNIVO_SESSION_SECRET`، مع حماية ملكية المستخدم في الاستعلامات.
- تطبيق ترحيلات Drizzle حتى `0009_session_and_material_limits.sql`، وسلسلة snapshot metadata المصححة.
- قيود تحقق أفضل للملفات والمواد ومهام المعالجة ومصادر إجابات الذكاء الاصطناعي.
- مواد مرفوعة وبحث grounded وتحليل Topics، مع اختبار Practice وFull Mock محفوظين؛ لا يجب كشف صحة الإجابة أو الدرجة أثناء الاختبار التجريبي النشط.
- Study Manager بهيوريستيات تراعي مواعيد الامتحان والوقت والإتقان والأخطاء والثقة ومراجعات البطاقات.
- اختيار المظهر الفاتح/الداكن، ودعم RTL للعربية، وكتالوجات لغة لـ14 لغة.
- GitHub Actions CI لتشغيل `pnpm check`, `pnpm test`, و`pnpm build`.

كانت حالة CI لالتزام كود التطبيق `b2b8bd2` **success**: [GitHub Actions run](https://github.com/mojtabahamed163-ai/studynivo-ai-study-coach/actions/runs/37113805625). بعد تحديث هذه الوثائق سيظهر تشغيل CI أحدث على `main`؛ تحقّق منه قبل أي نشر.

## ما تحقق فعلًا في هذه الجلسة

في مشروع Preview مؤقت مرتبط بحساب هذه الجلسة، وبقاعدة Manus جديدة فارغة:

1. فُعّلت قدرات Server وDatabase، وأُنشئت قاعدة بيانات جديدة.
2. طُبّقت ترحيلات Drizzle، بما فيها `0009_session_and_material_limits.sql`، على قاعدة تلك الجلسة.
3. نجح إنشاء مستخدم QA وتسجيل الدخول، وحُفظت مادة `Biology QA` في قاعدة البيانات.
4. اختُبر المظهر الفاتح ثم الداكن بصريًا؛ ظهر RTL للعربية في صفحة الدخول والإعدادات.
5. شوهدت فجوات ترجمة واضحة: بقيت تسميات مثل `Home`, `Subjects`, `Study plan`, `Review me`, `Progress`, و`Saved items` ونصوص من لوحة البداية/المواد بالإنجليزية داخل الواجهة العربية.

حساب الاختبار ومادة الاختبار موجودان فقط في قاعدة مشروع Preview المؤقت، وليسا ضمن GitHub. لا توجد كلمة مرور اختبار أو بيانات سرية في المستودع. قاعدة الحساب الجديد ستكون منفصلة وفارغة.

**ملاحظة تشغيل لتجنب الخطأ الذي واجهناه:** أول خادم بدأ في Terminal منفصل لم يرَ متغيرات Manus المدارة، فظهرت `Database is not available`. بعد إعادة تشغيله من Terminal/جلسة المشروع المرتبطة بـWebDev ظهرت متغيرات قاعدة البيانات والخدمات ونجح التسجيل. في الحساب الجديد شغّل `pnpm dev` من Terminal المشروع نفسه وبمجلد المشروع الصحيح؛ إذا تعذّر الاتصال، افحص وجود المتغيرات المطلوبة دون طباعة قيمها ثم أعد تشغيل الخادم من جلسة المشروع. لا تعدّل الكود لمعالجة غياب متغيرات بيئة غير محمّلة.

## ما لم يُنجز — ابدأ من هنا

1. **لم يكتمل رفع ملف فعلي أو فهرسته** على Preview في هذه الجلسة.
2. لم يُشغّل `Analyze topics` على مادة، ولم يُتحقق من إنشاء Topics من خدمة AI الحقيقية.
3. لم يُختبر Practice/Full Mock على المادة أو حفظ الإجابة والثقة والنتيجة أو استعادة التقرير بعد إعادة التحميل.
4. لم يُستكمل اختبار أن مفاتيح الإجابات والشرح والدرجات لا تتسرب أثناء اختبار Full Mock النشط.
5. **لم تُصلح فجوات الترجمة التي ظهرت.** طلب المستخدم أن يشمل الإصلاح جميع اللغات الـ14، وليس العربية فقط. يجب تدقيق النصوص الظاهرة في الواجهة وترجمة المفاتيح الناقصة إلى جميع اللغات المدعومة، ثم إضافة/تحديث اختبارات تمنع رجوعها إلى الإنجليزية. ملفات البدء: `client/src/i18n.ts`, `client/src/i18n.generated.ts`, `client/src/i18n.test.ts`, والنصوص في `client/src/App.tsx` ومكونات الواجهة.
6. لم يُنشر المشروع الجديد، ولا يوجد رابط إنتاج جديد بعد.
7. لا تنتقل قاعدة البيانات أو أسرار Manus أو مشروع WebDev عبر GitHub؛ يجب إعدادها داخل حساب Manus الجديد.

## إعداد مشروع الحساب الجديد

1. اربط حساب GitHub الذي يملك المستودع الخاص، أو أضف مستخدم GitHub الجديد بصلاحية مناسبة إلى المستودع. استخدم `mojtabahamed163-ai/studynivo-ai-study-coach` و`main`.
2. أنشئ **WebDev project جديدًا من هذا المستودع** داخل حساب Manus الجديد، مع Server وDatabase؛ لا تحاول ربط المشروع القديم، ولا تنشئ تطبيقًا منفصلًا من قالب فارغ.
3. استخدم إعدادات التشغيل الموجودة في المشروع والمنفذ `3000`. اترك النشر التلقائي مغلقًا إلى أن ينجح الفحص وE2E.
4. فعّل Manus Database وManus Service API/AI، وStorage، وSpeech عند اختبار الملفات الصوتية. تستخدم خدمات Manus المدارة؛ لا تطلب من المستخدم أسرار حسابه القديم.
5. اضبط `STUDYNIVO_SESSION_SECRET` من آلية الأسرار الآمنة للمشروع بقيمة عشوائية جديدة لا تقل عن 32 حرفًا. لا تضع القيمة في الدردشة أو GitHub أو ملف `.env` متتبع. يحصل `DATABASE_URL` من قاعدة Manus الجديدة. لا تنسخ بيانات قاعدة الحساب القديم.
6. نفّذ من جذر المستودع:

```bash
pnpm install --frozen-lockfile
pnpm check
pnpm test --run
pnpm build
pnpm db:migrate
pnpm dev
```

نفّذ `pnpm db:migrate` بعد تجهيز قاعدة Manus الجديدة وقبل اختبار وظائف قاعدة البيانات. لا تستخدم `db:push` بدلًا منه ولا تحذف/تُعد ترتيب migrations.

7. افحص من الخادم:

```bash
curl -fsS http://127.0.0.1:3000/api/health
curl -fsS http://127.0.0.1:3000/manus-routes.json
```

8. أصلح ترجمة الواجهة كاملة عبر اللغات الـ14 واختبرها، مع الحفاظ على الاتجاه RTL للعربية.
9. اختبر في Preview بحساب QA جديد وملف TXT تعليمي لا يحتوي تعليمات خارج نطاق المادة: إنشاء الحساب → إنشاء Subject → رفع ملف → اكتمال الفهرسة → Analyze topics → التحقق من Topics ومصادرها → Practice/Full Mock → الإجابة عن سؤال → إعادة التحميل واستعادة التقرير. تحقق أن Full Mock لا يكشف الإجابة أو الدرجة قبل نهاية المحاولة.
10. أعد تشغيل `pnpm check`, `pnpm test --run`, و`pnpm build`، وافحص `git diff --check` ونجاح CI. حدّث وثائق التسليم، ثم ادفع التغييرات إلى `main` دون force-push.
11. بعد نجاح الاختبارات، احفظ checkpoint في **مشروع الحساب الجديد** وانشره إلى رابط جديد. اختبر الرابط المنشور ودوّن عنوانه. لا تنشر من هذا الحساب إلى الموقع القديم ولا تدّعِ أن الرابط القديم قد تحدّث.

## أسرار وحدود مهمة

- لا توجد كلمات مرور أو مفاتيح API أو DSN في GitHub. `.env.example` يحتوي قيمًا شكلية للتوثيق فقط.
- لا تنقل `STUDYNIVO_SESSION_SECRET` أو `DATABASE_URL` من مشروع الجلسة المؤقتة؛ أنشئ سرًا وقاعدة جديدين.
- المسار الحالي للمصادقة هو البريد أو الهاتف وكلمة المرور. لا تضف أزرار Google/Apple/Microsoft غير العاملة.
- لا force-push، ولا تحذف migrations، ولا تستبدل المشروع بقالب فارغ.
- النشر على مشروع جديد يعني URL جديدًا وقاعدة مستقلة؛ ليس نقلًا للموقع أو لبياناته القديمة.
